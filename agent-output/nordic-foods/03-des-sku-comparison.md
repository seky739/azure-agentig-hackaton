## App Service Plan Trade-offs

| Criterion                     | B1 (Dev only)   | S1             | P0v3           | P1v3                    |
| ----------------------------- | --------------- | -------------- | -------------- | ----------------------- |
| Relative cost rank (unpriced) | 1 (lowest)      | 2              | 3              | 4 (PAYG); lower if reserved |
| VNet integration              | ✅ (see note)   | ✅             | ✅             | ✅                      |
| Private endpoint (inbound API)| ✅ (see note)   | ✅             | ✅             | ✅                      |
| Zone redundancy              | ❌              | ❌             | ✅ (Premium v2 to v4) | ✅ (Premium v2 to v4) |
| 1-year reservation           | ❌              | ❌             | ✅ (Premium v3 compute) | ✅ (Premium v3 compute) |
| Fit for 500 concurrent users | ⚠️ Dev only     | ⚠️ needs load test | ⚠️ needs load test | ✅ most headroom of the set (unquantified) |
| Fit for 99.9% SLA target     | ❌              | ⚠️ single zone | ✅ with zone redundancy | ✅ with zone redundancy |

Notes:

- Microsoft Learn lists VNet integration and private endpoints as supported from Basic upward. The repo rule in
  `sku-manifest.instructions.md` says VNet integration is "not on Basic". This conflict is flagged for the IaC Planner; B1 is
  priced as a candidate until it is resolved.
- Zone redundancy turns the whole plan zone redundant and needs Premium v2 to v4 (and the instance count the platform requires).
- Portal and private API share one plan per environment, so the plan SKU applies to both apps.

## Azure SQL Database Trade-offs

| Criterion                     | DTU Basic / S0 (Dev) | DTU S1 / S2 (Prod) | GP serverless Gen5 (Prod) |
| ----------------------------- | -------------------- | ------------------ | ------------------------- |
| Relative cost rank (unpriced) | Lowest               | Low to medium      | Depends on usage; needs explicit vCore-hour assumption |
| Cost predictability           | ✅ fixed             | ✅ fixed           | ⚠️ varies with load       |
| Seasonal 3x peaks             | ⚠️                   | ⚠️ manual scale-up | ✅ scales within configured vCore range |
| Auto-pause / resume           | ❌                   | ❌                 | ✅ General Purpose only; not suitable for always-on Prod |
| Private endpoint, Entra-only auth | ✅               | ✅                 | ✅                        |
| 1-year reservation            | ❌ (DTU not covered) | ❌                 | ⚠️ not evaluated          |
| Performance fit (p95 < 300 ms API) | Unverified      | Unverified         | Unverified                |

Notes:

- DTU capacity per tier and serverless vCore ranges were not verified from Learn this session; they are not quoted here.
- Backup storage redundancy defaults to geo-redundant (paired region). For GDPR in-region backups choose Local or Zone
  redundancy, and keep point-in-time-restore retention at or below 35 days to meet the backup expiry rule.
- Sweden South is a restricted-access region, so in-EU geo-replication is not freely available (DR is out of MVP scope).

## Supporting Services

| Service            | Option                | Trade-off                                                                       |
| ------------------ | --------------------- | ------------------------------------------------------------------------------- |
| Container Registry | Premium (only choice) | Costlier than Basic/Standard but required for private endpoints; shared by Dev and Prod to limit cost |
| Key Vault          | Standard (only choice)| No tier decision; Premium (HSM) is not required by any stated requirement        |
| Blob storage       | LRS (pinned) vs ZRS   | LRS keeps cost lowest but loses data on a zone-wide failure; invoices kept 7 years are regenerable from SQL, which mitigates the risk |
| Log Analytics      | Pay-as-you-go ingestion | Cost depends on ingestion GB, which the requirements do not supply             |
