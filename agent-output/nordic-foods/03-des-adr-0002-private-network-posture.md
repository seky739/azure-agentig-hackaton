## 🔍 Context

The API must not be internet-exposed and customer data holds GDPR PII. The approved assessment decides:

> Network posture | One VNet 10.0.0.0/16, per-environment subnets, 10 private endpoints, 5 private DNS zones | Baseline requirement; one VNet keeps cost low. Subnet plan confirmed at the gate.

and constrains the call path:

> The browser cannot call a private API, so the portal must proxy server-side, adding one hop to the p95 budget (2 s page, 300 ms API).

Source: [02-architecture-assessment.md](02-architecture-assessment.md), Architecture Decision Summary and Performance Assessment.

## ✅ Decision

Deploy one VNet `10.0.0.0/16` shared by Dev and Prod through separate subnets with one NSG each. The portal has public HTTPS ingress only; the API, SQL, Blob, Key Vault and Container Registry use private endpoints with public access disabled. The portal reaches the API server-side through VNet integration and the API private endpoint. Every private endpoint has a linked private DNS zone.

| Purpose                            | CIDR           | Delegation                       |
| ---------------------------------- | -------------- | -------------------------------- |
| App integration, Prod              | 10.0.0.0/26    | `Microsoft.Web/serverFarms`      |
| App integration, Dev               | 10.0.0.64/26   | `Microsoft.Web/serverFarms`      |
| Private endpoints, Prod and shared | 10.0.0.128/27  | None                             |
| Private endpoints, Dev             | 10.0.0.160/27  | None                             |
| GitHub runner                      | 10.0.0.192/27  | `GitHub.Network/networkSettings` |

## 🔄 Alternatives Considered

| Option                              | Pros                                | Cons                                                                  | WAF Impact                |
| ----------------------------------- | ----------------------------------- | --------------------------------------------------------------------- | ------------------------- |
| Public API with access restrictions | No private endpoint or proxy hop    | Breaks the requirement that the API is private and the security baseline | Security: -, Cost: +   |
| Separate VNet per environment       | Stronger Dev and Prod isolation     | More networks and peering to run; the assessment chose one VNet for cost | Security: +, Cost: -   |
| Browser calls the API directly      | No proxy hop                        | Not possible: the browser cannot reach a private API                  | Not applicable            |

## ⚖️ Consequences

### Positive

- Meets the private-data baseline without a jump host or Bastion.
- One VNet keeps network cost and operations low.

### Negative

- Private endpoints cost $73.60/month and private DNS $2.90/month.
- No WAF or DDoS layer in front of the public portal (declined by the user).
- Dev and Prod share one network boundary; separation rests on subnets and NSGs.
- The proxy hop consumes part of the 300 ms API p95 budget.

### Neutral

- Private DNS zone ownership against policy (DINE) is still open for Step 3.5.

## 🏛️ WAF Pillar Analysis

| Pillar      | Impact | Notes                                                                    |
| ----------- | ------ | ------------------------------------------------------------------------ |
| Security    | ↑      | Private endpoints, public access disabled, NSG per subnet.               |
| Reliability | ↓      | Private DNS failures can break resolution; runbook not yet written.      |
| Performance | ↓      | Added server-side hop for portal-to-API calls.                           |
| Cost        | ↓      | Private endpoints and DNS add $76.50/month, offset by a single VNet.     |
| Operations  | →      | Subnet plan is fixed at the VNet gate; runner size is confirmed at Step 4. |

## 🔒 Compliance Considerations

- Private endpoints keep PII-bearing data services off the public network, supporting GDPR safeguards.
- All regional resources stay in `swedencentral`.

## 📝 Implementation Notes

- Verify whether policy already deploys the private DNS zones before Step 4 creates project-owned zones.
- Record the maximum concurrent runners against `10.0.0.192/27`; reopen the size only if demand exceeds it.
- Control runner egress by domain; the feature does not allow TLS interception.
