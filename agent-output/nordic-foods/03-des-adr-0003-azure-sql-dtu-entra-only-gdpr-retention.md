## 🔍 Context

Orders, customers, inventory and delivery schedules need a relational store. Requirements set RTO 4 hours, RPO 1 hour, GDPR erasure within 30 days and a 7-year exception for orders, invoices and receipts. The approved assessment decides:

> Database | Azure SQL DTU, Entra-only; S2 Prod, S0 Dev | Predictable cost; serverless auto-pause is not useful for Prod.

> Backups and logs | Local SQL backup redundancy; PITR and logs at most 30 days | Keeps copies in-region and inside the GDPR erasure window.

Source: [02-architecture-assessment.md](02-architecture-assessment.md), Architecture Decision Summary and GDPR Erasure and Retention Control.

## ✅ Decision

Use Azure SQL Database on the DTU model with Entra-only authentication and public access disabled: Standard S2 for Prod ($73.61/month) and Standard S0 for Dev ($14.72/month). Set backup storage redundancy to Local and point-in-time restore retention to 30 days or less. Keep Log Analytics retention at 30 days. Apply the erasure control from the assessment: delete or pseudonymize live rows, redact invoice and receipt copies, let backups and logs expire, and re-apply a minimal deletion ledger after any restore.

## ⚖️ Consequences

### Positive

- Predictable monthly cost; Entra-only removes SQL passwords.
- Local backup redundancy keeps backup copies in-region and inside the 30-day window.
- Transaction log backups about every 10 minutes support the 1-hour RPO for point-in-time restore.

### Negative

- DTU databases cannot be reserved, so no SQL commitment saving exists.
- Basic and Standard DTU have no zone redundancy (see [ADR-0004](03-des-adr-0004-single-zone-prod-availability-posture.md)).
- DTU capacity of S2 and S0 was not verified; sizing has no load evidence.
- Restore time depends on database size, so the 4-hour RTO needs a timed restore test.

### Neutral

- Automatic backups cannot be exported or edited, so expiry is the deletion mechanism.

## 🏛️ WAF Pillar Analysis

| Pillar      | Impact | Notes                                                                 |
| ----------- | ------ | --------------------------------------------------------------------- |
| Security    | ↑      | Entra-only authentication, private endpoint, public access disabled.  |
| Reliability | ↓      | Local redundancy only; restore time unmeasured.                       |
| Performance | →      | DTU sizing is a price-proxy estimate pending the 500-user load test.  |
| Cost        | ↑      | Lowest tiers that meet repo floors; no reservation possible.          |
| Operations  | ↓      | Erasure runbook and deletion-ledger replay are new procedures.        |

## 🔒 Compliance Considerations

- GDPR: erasure within 30 days across live data, backups, logs and derived copies; secondary copies are deleted or irretrievable within the window.
- 7-year exception applies only to the legally required fields of orders, invoices and receipts.
- Michal Sakac is the accountable owner; acceptance of the retention field mapping is a prerequisite for Step 4.

## 📝 Implementation Notes

- Verify with an erasure test and a timed restore-and-replay test in Dev before go-live.
- Telemetry must not carry personal data or must stay within 30 days.
- Basic and Standard allow different PITR ranges (Basic 1 to 7 days); set the value explicitly.
