## 🔍 Context

SQL, Blob, Key Vault and the registry have public access disabled, so deployments and image pulls need a private path. The approved assessment decides:

> CI/CD | GitHub-hosted VNet runner with OIDC | No jump host or Bastion; runner minutes are GitHub billing.

> Container Registry | Premium | 1 shared registry | $50.69 | Only tier supporting private endpoints.

and requires:

> Both apps in Dev and Prod enable App Service VNet image pull (`vnet_image_pull_enabled` or equivalent), `privatelink.azurecr.io` resolves through the integration VNet, and each app identity holds AcrPull on the shared registry before deployment

Source: [02-architecture-assessment.md](02-architecture-assessment.md), Architecture Decision Summary, Resource SKU Recommendations and Security Requirements for Implementation.

## ✅ Decision

Deploy with a GitHub-hosted runner attached to the delegated subnet `10.0.0.192/27` using OIDC federated identity, with no jump host or Bastion. Use one shared Container Registry Premium with admin disabled, a private endpoint and Managed Identity (`AcrPull`) for image pull. Create the Terraform-state storage account in a separate bootstrap phase before the main backend is initialized.

## 🔄 Alternatives Considered

| Option                              | Pros                              | Cons                                                                       | WAF Impact                     |
| ----------------------------------- | --------------------------------- | -------------------------------------------------------------------------- | ------------------------------ |
| Jump host or Bastion for deployment | Familiar access path              | The assessment finds none is needed; adds an access surface to operate     | Security: -, Operations: -     |
| Registry below Premium              | Lower price than $50.69/month     | Private endpoints require Premium, so the baseline cannot be met           | Security: -, Cost: +           |
| Registry with public access         | No private endpoint or VNet pull  | Breaks the no-public-data-services baseline                                | Security: -                    |

## ⚖️ Consequences

### Positive

- No stored deployment credentials (OIDC) and no jump host to maintain.
- Image pull uses identity, not registry admin credentials.

### Negative

- Premium registry costs $50.69/month, the only tier that supports private endpoints.
- Runner subnet needs `GitHub.Network/networkSettings` delegation in the same subscription and region; the `/27` caps concurrent runners.
- Runner egress control by domain is still needed.
- `terraform init` cannot reach the state backend until its private endpoint, DNS link, role and runner connectivity exist.

### Neutral

- Runner minutes are billed by GitHub, not Azure, so they are outside the $348.77 estimate.

## 🏛️ WAF Pillar Analysis

| Pillar      | Impact | Notes                                                              |
| ----------- | ------ | ------------------------------------------------------------------ |
| Security    | ↑      | OIDC, private registry, no admin credentials, no jump host.        |
| Reliability | ↓      | Runner or DNS faults block deployments and image pulls.            |
| Performance | →      | No runtime effect after image pull.                                |
| Cost        | ↓      | Registry Premium is required for private access.                   |
| Operations  | ↓      | Bootstrap phase and a private image-pull connectivity check are new steps. |

## 🔒 Compliance Considerations

- Private registry and OIDC reduce credential exposure for a workload holding GDPR PII.

## 📝 Implementation Notes

- Step 4 readiness includes a private image-pull connectivity check and `AcrPull` before deployment.
- Add diagnostics for the registry and network resources, with 30-day retention for PII-bearing data.
- Record the runner egress allow-list and the maximum concurrent runners in the plan.
